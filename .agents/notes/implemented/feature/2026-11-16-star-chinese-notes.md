# Agent Note: Star 中文备注、项目设置弹窗改版

Status: implemented

## Problem

Star 卡片和编辑弹窗显示的是 GitHub 上的英文简介，只看项目名和英文简介很难判断项目是做什么的，也不方便记忆。编辑弹窗的「备注」默认填的就是英文简介，保存后英文简介原样成了备注。另外用户觉得项目设置弹窗不好看，「分组」下拉框是系统默认样式，「标签」输入框没有用处（卡片上不显示），管理菜单向左展开也别扭。

## Decision

- **中文简介直接写进现有的「备注」**，不新增字段：同步只更新 GitHub 元数据，从不碰备注，翻译结果写进去后不会被下一次同步覆盖。卡片和编辑弹窗本来就优先显示备注，不用改显示逻辑。
  - 只处理「没写过」的备注：备注为空，或者和 GitHub 简介一字不差（旧版编辑框把简介原样存成备注的情况）。用户自己写的备注一律不动；简介本来就以中文为主的跳过。
  - 写入时用读到的旧值做条件（`note is null` 或 `note = 旧值`），翻译期间用户刚好改了备注就保留用户写的。
  - 翻译提示词要求忠实原文、一句话 40 字以内、项目名和技术名词保留英文；每批 30 个、最多 3 批并发，在时间预算内能做多少做多少。
- **什么时候翻译**：
  - 每日定时同步后顺带翻译（预算 35 秒，路由 `maxDuration` 60 秒），没翻完的留到下一次。
  - 手动同步后，同步按钮接着反复请求 `POST /api/github/notes`（每次预算 45 秒），直到没有剩余或某次没有进展，按钮上显示「还剩 N 个」。
  - AI 没配置时安静跳过；密钥、权限这类错误直接停止后续批次。翻译出错不影响同步结果。
- **「AI 分析」按钮**：编辑弹窗的备注旁边。`POST /api/manage/ai-note` 读取项目的简介、语言、topics 和 README 开头（去掉代码块、HTML、图片和徽章，最多 3000 字），生成一到两句、60 字以内的中文备注，只填进输入框，用户保存后才生效；可以「恢复原来的备注」。
- **项目设置弹窗改版**：标题换成项目名，左边是项目头像（书签用网站图标），副标题是仓库链接、语言和更新时间；备注下方对照显示 GitHub 原始简介；「公开显示」改成整行可点的开关；底部操作区加分隔线。备注里 Enter 保存、Shift + Enter 换行。
- **下拉框美化**：对话框里的下拉框（分组、目标分组、Release 版本、AI 整理的目标分组）去掉系统外观，换成和输入框一致的玻璃样式和自绘箭头；支持可定制 select 的浏览器（Chromium 135+，`appearance: base-select`）连弹出的选项列表一起美化，其他浏览器保持系统列表。
- **去掉标签输入框**：编辑弹窗和添加书签弹窗都不再显示。保存时保留原有标签，已有标签仍参与搜索和 AI 整理。
- **管理菜单向上展开**：从「管理」按钮正上方竖排展开，右边缘与按钮对齐，选中数量徽标靠右。2026-11-17 起每个操作改成和角落按钮同尺寸的图标按钮：名称在悬停或键盘聚焦时显示在左侧（同时作为按钮的可访问名称），选中数量显示为右上角角标，没勾选时「移动」的名称提示先勾选；窗口高度不超过 400px 时改为在「管理」按钮左侧横排。AI 整理冒烟测试会检查这些按钮和角落按钮同尺寸、右对齐。

## Alternatives considered

- 新增 `description_zh` 字段单独存中文简介：可以在 GitHub 简介变化时重新翻译，但要多一次迁移；用户希望直接用现有的备注。代价是 GitHub 简介以后变化时，已经写进备注的中文不会自动更新，可以用「AI 分析」重新生成。
- 把中文翻译写进 `description`：每次同步都会被 GitHub 的英文覆盖，只能每天全部重翻。
- 批量翻译也读 README：每个项目多一次 GitHub 请求，几百个 Star 会明显变慢、更费 token；批量只用简介，需要更详细时再用「AI 分析」。
- 自己写下拉组件替代原生 select：样式完全可控，但键盘操作和读屏要自己实现；原生 select 加可定制样式，渐进增强更稳。

## Verification

- `npm test`：新增中文备注的单元测试，覆盖哪些备注需要翻译、中文判断、翻译提示词编号与结果映射、README 清理、「AI 分析」提示词和结果清理，全部 53 项通过。
- ESLint、TypeScript 检查通过；webpack 生产构建通过，并确认产物 CSS 里保留了 `::picker(select)`、`base-select`、开关和管理菜单的样式。
- 本机回环连接被系统拦截（node、PowerShell、curl 连 127.0.0.1 都返回 WSAEACCES），Turbopack 构建、开发服务和端到端测试都无法在本机运行，界面没有截图核对；需要在线上部署后实际看一次。没有用真实密钥测试翻译和「AI 分析」。

## Consequences

- 翻译和「AI 分析」使用 AI 整理的同一套配置（`AI_BASE_URL`、`AI_API_KEY` 等）；没配置时同步照常进行，只是不翻译。
- 几百个 Star 第一次补齐需要多次请求，手动同步会自动接着做；每日定时同步每次只处理一部分。
- 备注里的中文是 AI 生成的，GitHub 简介后来变化时不会自动更新。
- 「AI 分析」会把项目 README 的开头发给配置的 AI 渠道。
